## Conceptos aprendidos

### 1. Arquitectura de ROS 2

ROS 2 es un framework de middleware, no un sistema operativo. Permite que distintos programas (nodos) se comuniquen entre sí de forma estructurada.

Los 5 conceptos core:

- **Nodo** — proceso independiente que hace una sola cosa (sensor, control, visión)
- **Topic** — canal de comunicación con nombre. Un nodo publica, otros suscriben. Asíncrono
- **Message** — tipo de dato que viaja por un topic (`std_msgs/Float32`, `px4_msgs/VehicleLocalPosition`, etc.)
- **Service** — comunicación request/response síncrona para tareas puntuales
- **Action** — como un service pero para tareas largas con feedback (usado en Nav2)

### 2. Estructura de un workspace ROS 2

```
aprendizaje_ros/
├── src/                     ← código fuente de los paquetes
│   └── drone_tutorial/
│       ├── drone_tutorial/
│       │   ├── __init__.py  ← marca la carpeta como paquete Python
│       │   └── altimeter_node.py
│       ├── package.xml
│       ├── setup.cfg
│       └── setup.py
├── build/                   ← generado por colcon build
├── install/                 ← generado por colcon build
└── log/                     ← logs de compilación
```

### 3. ¿Qué es sourcear?

`source archivo.bash` le dice a la terminal dónde están las herramientas y paquetes instalados. Sin sourcear, la terminal no encuentra `ros2` ni `px4_msgs`.

Se pierde al cerrar la terminal, por eso se agrega al `.bashrc` para que sea automático en cada terminal nueva.

### 4. Sistema de coordenadas NED de PX4

PX4 usa el sistema **NED** (North-East-Down): el eje Z apunta hacia abajo. Cuando el dron sube, Z se vuelve más negativo. Por eso en el código siempre se hace `altitud = -msg.z`.

### 5. QoS en ROS 2 con PX4

PX4 publica sus topics con política `BEST_EFFORT`. Si el suscriptor usa el QoS por defecto (`RELIABLE`), son incompatibles y no llega ningún dato aunque el topic aparezca en `ros2 topic list`. Siempre hay que declarar el QoS explícitamente al suscribir topics de PX4.

### Paso 3 — Problema con px4_msgs

Al intentar leer topics de PX4 apareció el error:
```
The message type 'px4_msgs/msg/VehicleLocalPosition' is invalid
```

**Causa:** `px4_msgs` estaba compilado en otro workspace (`~/Workspace/Programacion/ros2_ws`) pero no estaba sourceado.

**Solución:** Sourcear ese workspace antes de usar los mensajes de PX4:

```bash
source /opt/ros/jazzy/setup.bash
source ~/Workspace/Programacion/ros2_ws/install/setup.bash
```

Para hacerlo permanente se agregó al `.bashrc`:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
echo "source ~/Workspace/Programacion/ros2_ws/install/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

### Paso 4 — Verificar datos reales de PX4

Con todo sourceado correctamente:

```bash
ros2 topic list | grep fmu
# Aparecen todos los topics: /fmu/out/vehicle_local_position_v1, etc.

ros2 topic echo /fmu/out/vehicle_local_position_v1
```

Nota importante: los topics tienen sufijo de versión (`_v1`, `_v4`). Usar los nombres exactos en el código.

### Paso 5 — Primer nodo real: altimeter_node.py

Se creó el primer nodo Python que lee altitud real del dron simulado:

```python
# ~/Workspace/Programacion/aprendizaje_ros/src/drone_tutorial/drone_tutorial/altimeter_node.py
import rclpy
from rclpy.node import Node
from px4_msgs.msg import VehicleLocalPosition
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy

class AltimeterNode(Node):
    def __init__(self):
        super().__init__('altimeter_node')

        qos = QoSProfile(
            reliability=ReliabilityPolicy.BEST_EFFORT,
            history=HistoryPolicy.KEEP_LAST,
            depth=10
        )

        self.subscription = self.create_subscription(
            VehicleLocalPosition,
            '/fmu/out/vehicle_local_position_v1',
            self.recibir_posicion,
            qos
        )

        self.get_logger().info('Altímetro iniciado ✓')

    def recibir_posicion(self, msg):
        altitud = -msg.z  # NED: z negativo = arriba
        self.get_logger().info(f'Altitud real: {altitud:.2f} m')

def main():
    rclpy.init()
    nodo = AltimeterNode()
    rclpy.spin(nodo)
    nodo.destroy_node()
    rclpy.shutdown()
```

## Errores encontrados y soluciones

| Error | Causa | Solución |
|---|---|---|
| `aprendizaje_rospkg: command not found` | Typo en el comando | Usar `ros2 pkg create` |
| `The directory already exists` | El paquete ya existía | No es error, colcon build igual compila |
| `px4_msgs/msg/VehicleLocalPosition is invalid` | px4_msgs no sourceado | Agregar `source ros2_ws/install/setup.bash` al `.bashrc` |
| `Package 'drone_tutorial' not found` | `colcon build` no se corrió | Correr `colcon build` desde la raíz del workspace |
